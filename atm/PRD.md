# PRD: 환율 ATM — 현금 넣으면 오늘의 환율로 바로 나오는 재미있는 환전 경험

| 항목 | 내용 |
|---|---|
| 형식 | Lean PRD (MVP) |
| 작성일 | 2026-10-21 |
| 개발 기한 | 2시간 |
| 상태 | Draft |

> 표시: **[가정]** 은 사용자 입력에 없어 임의로 채운 항목입니다. 검토 후 수정해주세요.

## 1. Executive Summary

ATM 기기에 현금을 넣으면 **오늘의 환율**로 즉시 환전되어 외화가 나오는 서비스입니다. 핵심은 환전 자체보다 **"환율을 확인하는 경험"을 재미있게 만드는 것**입니다. 환율 확인은 숫자만 나열되어 지루합니다. 이 지루함을 게임 같은 연출과 인터랙션으로 바꿔, 트렌드에 민감한 2030 세대가 매일 다시 찾게 만드는 것이 목표입니다.

2시간 안에 만들어야 하므로 실제 결제·하드웨어 연동은 제외합니다. 웹 기반 ATM 시뮬레이션으로, 현금 투입 → 실시간 환율 적용 → 환전 결과 연출까지의 핵심 흐름을 구현합니다.

## 2. Problem Statement

- 환율 확인 경험이 지루합니다. 숫자 표와 그래프를 보는 것이 전부입니다.
- 환율을 확인할 동기가 약해 재방문할 이유가 없습니다.

## 3. Goals & Success Metrics

**목표:** 환율 확인에 재미있는 경험을 더한다.

| 구분 | 지표 | 목표치 **[가정]** |
|---|---|---|
| North Star | 동일 유저가 7일 연속(또는 7일 중 5일 이상) 방문하는 비율 | 7일 리텐션 30% 이상 |
| 보조 | 세션당 환전 시도 횟수 | 2회 이상 |
| 보조 | 세션 체류 시간 | 1분 이상 |

측정 방법: 익명 사용자 ID를 localStorage에 저장하고 방문 날짜를 기록합니다. MVP에서는 7일 방문 이력을 확인할 수 있으면 충분합니다.

## 4. Target User

**트렌디한 2030 세대**
- 해외여행, 해외직구, 해외주식으로 환율에 관심이 있습니다.
- 앱 하나를 정보 전달만 기준으로 쓰지 않고, 재미와 공유할 만한 경험을 중시합니다.
- 모바일 중심으로 사용합니다.

## 5. User Stories & Acceptance Criteria

### US-1. 현금 투입 (P0)
As a 사용자, I want to 원화 금액을 ATM에 넣고, So that 환전될 금액을 확인할 수 있다.

- 금액 입력 또는 지폐 투입 인터랙션으로 원화 금액을 지정할 수 있다.
- 최소·최대 금액을 벗어나면 안내 문구가 표시된다. **[가정]** 1,000원 ~ 1,000,000원
- 숫자가 아닌 값은 입력되지 않는다.

### US-2. 오늘의 환율로 환전 (P0)
As a 사용자, I want to 오늘의 환율이 적용된 결과를 보고, So that 지금 내 돈의 가치를 알 수 있다.

- 환전 시점의 환율 API 값을 사용하고, 적용 환율과 기준일을 화면에 표시한다.
- 환전 결과(외화 금액)는 소수점 둘째 자리까지 표시한다.
- 통화는 USD, JPY, EUR 중 선택할 수 있다. **[가정]**
- 환율 API가 실패하면 에러 안내와 재시도 버튼을 보여준다.

### US-3. 재미있는 환전 연출 (P0)
As a 사용자, I want to 돈이 나오는 과정이 게임처럼 연출되길, So that 환율 확인이 지루하지 않다.

- 환전 시 ATM 동작 애니메이션이 재생된다(지폐가 들어가고 외화가 나오는 연출).
- 연출은 5초 이내에 끝나고, 건너뛰기 버튼이 있다.
- 연출이 끝나면 결과 카드가 표시된다.

**재미 인터랙션 (P0는 1~2번, 나머지는 P1)**
1. **지폐 투입:** 금액을 정하면 지폐 이미지가 ATM 투입구 쪽으로 드래그(또는 탭)해 넣는 동작으로 이어진다. 지폐가 빨려 들어가는 모션과 기계 진동이 따라온다.
2. **현금 배출:** 외화 지폐가 하단 배출구에서 한 장씩 튀어나오고, 사용자가 탭해서 "가져가기"를 해야 결과 카드가 열린다.
3. **숫자 롤링:** 외화 금액이 0에서 최종값까지 슬롯머신처럼 빠르게 올라가며 멈춘다.
4. **등락 리액션:** 전일 대비 환율이 올랐으면 초록(상승), 내렸으면 빨강(하락) 이펙트와 이모지 반응(🚀 / 😢)을 보여준다. 변동이 없으면 중립 반응을 보인다.
5. **연속 방문 스탬프:** 방문할 때마다 오늘의 스탬프를 찍는 연출을 보여주고, 7일 연속 방문 시 특별 연출(축하 효과)을 보여준다.
6. **기기 반응:** 키패드를 누르면 눌림 효과가 나고, 모바일에서 지원되면 짧은 진동(`navigator.vibrate`)을 준다.
- 모든 인터랙션은 `prefers-reduced-motion`이 켜져 있으면 단순 전환으로 대체한다.
- 인터랙션이 환율 확인과 결과 확인을 방해하지 않도록, 건너뛰기 버튼으로 언제든 결과 카드로 이동할 수 있다.

### US-4. 매일 돌아올 이유 (P1)
As a 사용자, I want to 어제보다 환율이 올랐는지 내렸는지 바로 보고, So that 내일도 확인하고 싶다.

- 전일 대비 환율 등락(▲▼, %)을 결과 카드에 표시한다.
- 연속 방문 일수를 표시한다. (예: "3일 연속 방문 🔥")

### US-5. 결과 공유 (P2, 시간 남으면)
As a 사용자, I want to 결과 카드를 공유하고, So that 친구에게 보여줄 수 있다.

- 결과 카드를 이미지로 저장하거나 링크를 복사할 수 있다.

## 6. Scope

**In scope (MVP, 2시간)**
- 단일 HTML 파일 기반 ATM 시뮬레이션 화면 (모바일 우선)
- 원화 금액 입력 → 외화 환전 결과
- 실시간 환율 API 연동 (무료 API) **[가정]**
- 환전 연출 애니메이션
- 전일 대비 등락, 연속 방문 일수 (P1)

**Out of scope**
- 외화 → 원화 환전 (환전 방향은 원화 → 외화 한 방향만 지원)
- 실제 현금 투입·지급 하드웨어 연동
- 실제 결제, 계좌, 본인인증, 금융 거래
- 회원가입·로그인
- 사용자 간 랭킹, 푸시 알림
- 서버/DB (localStorage로 대체)

## 7. Technical Considerations

- **스택:** HTML만으로 구현한다. 단일 `index.html` 파일에 CSS·JS를 인라인으로 작성하고, 프레임워크·빌드 도구·서버는 쓰지 않는다. 브라우저에서 열면 바로 동작해야 하며, 환율 API는 클라이언트에서 `fetch`로 호출한다.
- **환율 API:** Frankfurter v2 (`https://api.frankfurter.dev/v2/rates?base=KRW`). 무료·키 불필요이며 CORS `*`를 허용해 `file://`로 연 HTML에서도 호출 가능함을 확인했다. 응답은 `[{date, base, quote, rate}]` 배열이다.
- **전일 환율:** `&date=YYYY-MM-DD` 파라미터로 과거 환율을 조회할 수 있어 US-4 등락 표시가 가능하다. 주말·공휴일에는 직전 영업일 값이 오므로 `date`가 같으면 등락을 계산하지 않는다.
- **정밀도:** `base=KRW`는 `rate`가 소수점 5자리로 반올림되어(USD 0.00075) 환전 결과에 오차가 생긴다. 외화를 base로 조회(`base=USD&quotes=KRW` → 1329.09)해 역수로 환산하면 정확하다. (미해결 질문 6 참고)
- **데이터 저장:** 방문 이력은 localStorage에 저장한다(개인정보 없음).
- **성능:** 환율 조회는 3초 이내 응답을 목표로 하고, 실패 시 마지막 성공값을 캐시로 보여준다.
- **면책:** 화면에 "시뮬레이션이며 실제 환전이 아닙니다"를 명시한다. 금융 서비스로 오인되지 않게 하기 위함이다.

## 8. Design & UX Requirements

- 디자인 스타일: `DESIGN.md`(토스 디자인 시스템)의 색상, 타이포, 컴포넌트 규칙을 따른다. 깔끔한 톤에 재미는 연출과 인터랙션으로 더한다.
- ATM 기기 외형: `img/`의 참고 이미지를 따른다. 회색 본체, 상단 파란 "ATM" 간판, 파란 화면의 모니터부, 키패드, 카드·영수증 투입구, 하단 현금 배출구로 구성하고 CSS로 재현한다. 기기 화면 안의 UI는 토스 스타일로 그린다.
- 톤: 2030 세대가 좋아할 만한 트렌디하고 가벼운 분위기
- 모바일 세로 화면 우선, 한 손 조작을 고려한다.
- 핵심 흐름은 3단계(금액 입력 → 연출 → 결과)를 넘지 않는다.
- 접근성: 텍스트 명도 대비 4.5:1 이상, 애니메이션 건너뛰기와 `prefers-reduced-motion` 대응.
- 버튼 문구는 일관되게 유지한다(예: "환전하기", "다시 하기").

## 10. Risks & Mitigation

| 리스크 | 대응 |
|---|---|
| 2시간 내 완성 못 함 | P0만 먼저 완성, P1·P2는 시간이 남으면 진행 |
| 환율 API 장애 | 실패 시 에러 안내·재시도, 마지막 성공값 캐시 (CORS는 확인 완료) |
| `base=KRW` 환율 반올림 오차 | 외화 base 조회 후 역수 환산 (미해결 질문 6) |
| 연출에 시간을 과하게 씀 | 연출은 CSS 애니메이션 위주로 제한, 40분 타임박스 |
| 실제 환전 서비스로 오해 | 시뮬레이션 면책 문구 상시 노출 |
| 재미 요소가 리텐션으로 이어지지 않음 | MVP 후 방문 데이터로 검증하고, 일일 변화 요소(등락, 연속 방문)를 보강 |

## 11. Dependencies & Assumptions

- 무료 환율 API를 사용할 수 있다.
- 사용자는 모바일 브라우저로 접속한다.
- 7일 리텐션은 MVP 배포 후 1주일 뒤에야 측정 가능하다.
